# LayCal SEO Audit — 2026-10-10

**Scope:** https://laycal.com (live crawl 2026-10-10) + repository at `/Users/mac/Desktop/SaaSs/saas-template` (Next.js 15.4.10, App Router, Vercel). Read-only; nothing was modified.

**Evidence standard:** everything below is labeled **VERIFIED** (observed in code or live HTTP responses), **OBSERVED** (seen in third-party search results — note: a search API, not live Google SERPs), or **HYPOTHESIS**. No search volumes, rankings, traffic, or backlink numbers appear anywhere in this report because none were available.

---

## 1. Executive summary

LayCal has a solid technical foundation — full server-side rendering, clean heading hierarchy on marketing pages, real 404s, Brotli, HSTS, a working MDX blog pipeline, and intentional 301s for retired pages. That puts it ahead of most early-stage SaaS sites.

However, three problems materially cap organic growth:

1. **A sitewide canonical/host conflict.** The live site forces `www.laycal.com` (308), but every canonical, every `og:url`, and the robots.txt sitemap line point to the apex `laycal.com` — which redirects. Google is being told on every page that the "real" URL is one that redirects. This is the single highest-confidence defect.
2. **The site does not address the stated target market.** The objective is home-service businesses, but no indexable page targets that audience. The positioning docs (`LANDING_REDESIGN_BRIEF.md`) describe B2B/SDR buyers; the hero mentions "HVAC, e-commerce, B2B" generically; the six comparison assets target dialer/phone-system buyers (JustCall, Nooks, Aloware…), not the tools a home-services owner actually shortlists (Hatch, Sameday, Avoca, Rosie, Podium).
3. **Metadata inheritance bugs** cause at least 5 public routes (`/terms`, `/status`, `/support`, `/sign-in`, `/sign-up`) to share the homepage's title, description, and canonical — a duplicate-title cluster plus pages canonicalizing themselves to the homepage.

The encouraging news: the observed SERPs for home-services queries ("AI appointment setter for contractors", "AI receptionist for [trade]", "missed call text back software") are populated by small vertical vendors, not entrenched incumbents. The niche looks winnable — but demand is **unverified** without keyword tooling (see §9).

## 2. Technical SEO and indexability — verified findings

**Critical**

- **Host/canonical conflict (sitewide).** `https://laycal.com` → 308 → `https://www.laycal.com/` (VERIFIED, curl). Yet canonicals use apex: `<link rel="canonical" href="https://laycal.com">` on the homepage (VERIFIED live HTML), driven by `metadataBase: 'https://laycal.com'` (`src/app/layout.tsx:19`). The sitemap emits `www.laycal.com` URLs (`src/app/sitemap.ts:7`), while robots.txt declares `Sitemap: https://laycal.com/sitemap.xml` — a redirecting URL (`src/app/robots.ts`). Three different host signals across canonicals, sitemap, and robots. Also: `http://laycal.com` → apex → www is a 2-hop chain.
- **Canonical inheritance bug.** Root layout sets `alternates.canonical: "/"` (`layout.tsx:20-22`); Next.js merges this into pages without their own canonical. VERIFIED live: `/terms` and `/status` render the homepage title/description and canonicalize to `https://laycal.com`. Affected: `/terms`, `/status`, `/support`, `/sign-in`, `/sign-up` (all client components or metadata-less routes; `/terms` is `'use client'` at `src/app/terms/page.tsx:1`).
- **Sitemap contains a dead URL.** `/support` is in the sitemap (priority 0.6) but returns **404** live and is auth-gated in middleware (`src/middleware.ts:10-26`) — the sitemap, middleware, and `ClientLayoutWrapper.tsx:13` marketing-route list disagree about what `/support` is.
- **Fabricated lastmod.** The 10 static sitemap routes carry lastmod = request-generation time (VERIFIED: two fetches 7 minutes apart returned different lastmods). Google ignores unreliable lastmod and it taints the real dates on blog posts.

**Moderate**

- **Duplicate H1 on all 6 blog posts.** Template renders post title as H1 (`src/app/blogs/[slug]/page.tsx:351`) and every markdown body also starts with `# …` — VERIFIED in live HTML (two `<h1>` per post).
- **No OG image site-wide except blog posts.** `twitter:card: summary_large_image` is declared but `og:image` count is 0 on homepage, contact, comparison pages (VERIFIED live grep). And 5 of 6 blog posts share the same banner image.
- **Structured data gaps.** One JSON-LD block total: `SoftwareApplication` injected client-side (`src/components/landing/providers.tsx:45-78`), with `offers.price` hydrated by a client fetch to `/api/pricing` — crawlers may see the $0.07 default. No `Organization`, no `FAQPage` despite a real FAQ accordion (`src/components/landing/sections.tsx:164-197`), no `Article/BlogPosting` on posts. `LANDING_REDESIGN_BRIEF.md:146` says "preserve the two JSON-LD blocks" — one was lost in the redesign.
- **Public debug endpoint.** `/sitemap-debug` returns server internals (`process.cwd()`, file listings). Indexable, sensitive, should be removed.
- **Sign-in/sign-up return 200** with `index,follow` and homepage canonical — thin indexable auth pages (mitigated only by absence from sitemap).

**Minor / hygiene**

- No redirect `/blog` → `/blogs` (singular 404s).
- ~4.5 MB of unreferenced placeholder PNGs shipped in `public/` (filenames contain spaces); dead `src/app/head.tsx` preloads; homepage HTML is 243 KB with 23 JS chunks; sitemap has a hardcoded 6-post fallback list that silently goes stale (`sitemap.ts:82-119`).
- `eslint.ignoreDuringBuilds` and `typescript.ignoreBuildErrors: true` (`next.config.ts:26-31`) — an SEO-impacting regression can ship silently.

**Verified non-issues:** full SSR on all marketing pages; single H1 on homepage; proper 404 status codes (no soft-404s); valid robots.txt; manifest/favicons present; images via `/_next/image`; intentional 301s from retired pages (`/features`, `/pricing`, `/about`, `/speed-to-lead`, etc., `next.config.ts:37-45`); no `noindex` accidents.

## 5. Landing-page quality and conversion

- **Homepage is well-built for conversion:** single H1 ("Call every new lead in under a minute."), real FAQ, pricing anchor, demo CTA (Calendly). VERIFIED.
- **But it speaks to no one specifically.** "HVAC, e-commerce, B2B" in one breath dilutes the home-services pitch. A contractor should see their trade, their missed-call problem, and a stat like Invoca's 27% within one viewport.
- **Comparison pages are a doorway-pattern liability.** `/justcall-alternative` and `/nooks-alternative` are near-identical templates differing only by brand name (`page.tsx:9` in each), and both claim "95% cheaper" (`nooks-alternative/page.tsx:34`) — an unverified comparative claim. Google's spam policies explicitly name templated doorway pages; two near-duplicate pages also cannibalize each other's link equity pattern.
- **Cannibalization pairs (VERIFIED):** `/justcall-alternative` vs `/blogs/justcall-alternatives-2026`; `/nooks-alternative` vs `/blogs/nooks-alternative-2026`. Two URLs per keyword cluster, no canonical or internal-link signal declaring the primary.

## 6. Internal linking and architecture

- **Nav is a dead end for SEO:** `site-nav.tsx:19-24` links only to on-page anchors (`#how`, `#features`, `#pricing`, `#faq`) — no path from the nav to `/blogs`, comparison pages, or use-case pages.
- **The footer carries the entire internal link graph** (`sections.tsx:225-276`) — real `<Link>`/`<a>`, which is good, but it's the *only* discovery path to comparison pages.
- **Blog posts don't template-link to the comparison landing pages** — posts interlink with each other (related-posts module, good) but the commercial pages receive links only from the footer.
- `/status` is in the sitemap but linked from nowhere — orphaned.
- Architecture gap: no `/industries/` or `/compare/` hub exists; each new trade or competitor page would currently hang off the footer alone.

## 8. 30-day roadmap

**Week 1 — Technical trust (actions 1–3).** Host/canonical alignment, metadata inheritance, sitemap/debug-endpoint repair. Ship together; they're small, independent, and every subsequent content action depends on them. Re-crawl after deploy.

**Week 2 — SERP presentation (actions 7, 8 + H1 fix).** Structured data, OG images, blog template cleanup. Set up GSC + GA4 baselines **before** content ships — there is currently no measurement foundation.

**Week 3 — Commercial pages (actions 4, 5, 6).** Fix the two cannibalization pairs, build the first home-services page, rewire nav/blog internal links.

**Week 4 — Content program kickoff (actions 9, 10).** Publish the statistics asset; draft the first real-competitor comparison page (recommend Sameday or Podium — observed price-objection demand); write the keyword-to-URL map covering the clusters in §3 before creating any further pages.

## 9. Missing data — required to complete this audit

These cannot be verified from code, curl, or search APIs, and no recommendation above secretly depends on them:

1. **Google Search Console** — actual indexation status, which queries already generate impressions (the redesign brief claims the site "gets meaningful SEO traffic from 'JustCall alternative' queries" — unverified), canonical-selection decisions Google has already made.
2. **GA4 / Vercel Analytics export** — organic sessions, demo-booking conversion by landing page (the `@vercel/analytics` and GTM plumbing exists; no data was available).
3. **Keyword tool (Ahrefs/Semrush/Google Keyword Planner)** — volumes and difficulty for every cluster in §3. All demand labels there are UNVERIFIED by design.
4. **Core Web Vitals field data (CrUX/PageSpeed Insights)** — the 243 KB HTML / 23-chunk homepage is a lab-side smell, not a measured problem.
5. **Backlink profile** — needed to judge whether comparison pages can rank at all yet, and to size the link-magnet investment in action 10.
6. **A headless-browser render check** — raw HTML only was verified; JS-rendered DOM diffs (e.g., the pricing hydration that also feeds JSON-LD) weren't exercised.

**Bottom line for reviewers:** actions 1–4 and 6–8 rest on verified code/HTTP evidence and are safe to implement immediately. Actions 5, 9, and 10 are evidence-informed strategic bets whose SERP observations are real but whose demand is unverified — gate the *scale* of the content program (not its start) on keyword data and 4–6 weeks of GSC impressions.
